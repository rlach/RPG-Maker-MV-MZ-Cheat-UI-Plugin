# DESIRE FORCE card image LoadError (2.2.12)

## Evidence

Read-only inspection of `G:\!NEWORDER\GAMES\RJ01772465\[Kimochi] RJ01772465\DESIRE FORCE` identifies the enabled `NLM_CardItemSelectMZ` 1.2.1 plugin (MZ). Item 13 and 14 originally use `<CIPic:ドレイン>` and the file `img\pictures\ドレイン.png` exists. The item_note translation cache translates asset metadata payloads, for example `<CIPic:サナカード>` into `<CIPic:Sana Card>`. Those payloads are filenames, not display text.

NLM loads CIPic/CSPic backgrounds and CILayer/BILayer/CSLayer overlays through ImageManager.loadPicture. The same metadata is used by equipment previews, OnlyOneBattleStatus and common-event scripts (events 63, 66 and 67). Merely patching the item-list draw method would leave those routes broken. The fallback-interpreter diagnostic does not explain the missing image paths.

## Change

The dedicated NlmCardItemSelectTranslator activates only when NLM_CardItemSelectMZ is enabled. At the shared picture-loading boundary it resolves a proven translated card-file alias to the original asset tag from the database object's canonical \_translateOriginal.note snapshot. Evidence for the alias may come from the current note, metadata or the matching note-cache entry. It covers items, skills, weapons and armor. No reverse lookup of translated display names is used.

An authored original filename takes priority over an alias. Conflicting aliases are left unchanged. Other filenames, empty arguments, the native loader receiver and extra arguments are preserved. This compatibility repair stays active when text translation is disabled because already-applied translated note metadata may still be present. It never changes database objects, saves or cache entries and never translates graphics.

## Validation

Regression tests cover activation/retry, all five filename tags, item/skill/equipment tables, current metadata and cached aliases, unchanged authored English assets, ambiguity, repeated loading, disabled text translation and source/cache preservation. The whole test suite, formatting, lint, registry and duplicate checks are run separately. Live game playback and battle interaction remain unverified. No deployment or source-game edits were performed.
